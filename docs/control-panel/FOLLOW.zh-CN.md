# Windows 智能跟随

本功能属于个人 fork 的控制面板，不替代原 KDE Connect 插件。

## 设置

1. 在电脑“桌面控制”中新增页面，选中要绑定的页。
2. 将“页面模式”切换到“智能跟随”，点击“识别当前程序”。
3. 保持识别窗口打开，点击目标软件，等待片刻，再回到 KDE Connect。
4. 弹窗显示程序名，例如 `notepad++.exe`。可以复制名称，或直接点击“绑定到当前页”。“页面名称 / 应用绑定”里也可以手工填写或使用当前识别结果。
5. 手机进入该电脑的“控制面板”。以后切到目标程序，手机会收到电脑发布的活动页；未知程序回到首页。

程序绑定和页面显示名独立：页面可以叫“编辑器快捷键”，绑定仍为 `notepad++.exe`。匹配忽略大小写，输入路径时仅保留文件名；扩展名也参与匹配。同名绑定按页面顺序取第一项，建议每个程序只绑定一页。

## 稳定性与优先级

- 每 200 毫秒采样；同一个新程序持续至少 400 毫秒才采用。短暂窗口切换、无法读取的窗口、无前台窗口会取消尚未确认的候选，不覆盖最后一次稳定结果。
- KDE Connect 自己的窗口不会打断跟随。目标程序拥有的对话框按其根所有者窗口识别，不使用窗口标题匹配。
- 手机手动切页优先：保留该页，直到前台程序稳定变化。改变背景色等无关配置不会取消手动选择；切换模式或删除手动选定的页面会重新选取有效页。
- 修改程序绑定后，自动跟随目标会重新计算，不要求用户再次切走再切回；若手机仍处于手动覆盖，则继续尊重手动选择。
- 跟随仅改变运行时状态，不为每次切换写入配置修订号。所有配对控制器接收同一活动页。
- 快捷键仍发送给操作系统当前真正的前台窗口，不会擅自激活绑定程序。执行前应让要操作的软件位于前台。

## 边界与隐私

当前仅 Windows 提供原生识别；其他平台明确提示不支持。关闭智能跟随模式后停止采样。受权限限制而不能读取的进程不会被强行提权访问；此时保留上一次稳定识别结果。UWP 宿主窗口、提权窗口、系统任务切换器和长时间运行还需要进一步实机回归，不能从普通窗口测试推断全部兼容。

识别仅临时查询可执行文件路径并提取文件名，不读取窗口标题、文档内容或命令行，不向手机发送完整路径。界面中的复制按钮只有点击时才写入剪贴板。

原生接口依据微软文档：[前台窗口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow)、[根所有者窗口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getancestor)、[查询进程映像名](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew)。

## 验证入口

- 自动化：`panelforegroundtest`、`panelruntimetest`、`panelpeertest`、`paneleditortest`；Android 的 `PanelSessionTest` 验证跟随状态不改写配置、过期状态被拒绝。
- 交互检查：Windows 构建目录中的 `panelforegroundintegration.exe` 会启动自己的临时子窗口，使用生产识别器验证原生前台进程名。退出码 0 且输出 `success: true` 才算通过；8 秒未获得前台或权限不足时返回非零，不自动算作通过。测试会关闭自己创建的子进程。
- `panelforegroundintegration.exe --window` 单独显示最多 60 秒的自有窗口，可用于配对手机的自动切页联调。它不属于最终安装包。
