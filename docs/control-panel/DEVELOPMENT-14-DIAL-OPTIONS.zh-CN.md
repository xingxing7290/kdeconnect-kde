# 阶段十四：表盘、外观设置与焦点边界开发

日期：2026-11-12。上一个节点已按用户要求输出 0.1.0-alpha.1 体验版。本批恢复“先完成全部功能开发，最后统一测试”的顺序，只改控制面板模块及其测试，不重新构建或替换体验版产物、标签、校验值和 GitHub 附件。

## 本批功能修改

桌面 PanelEditor / PanelDialGallery / ControlDashboard：

- 表盘选择确认不再先关闭再尝试保存。保存成功才关闭；存储锁占用、目录/写入/备份失败时保留弹窗并显示原因，不制造“已经保存”的假象。
- 表盘确认、城市/文本/空闲参数设置和取色器记录打开时的配置 revision，经新增的受检接口保存。配置已变化则拒绝旧弹窗覆盖；最终磁盘写入仍复用 PanelStore 的锁与修订检查。
- 设置保存失败保留输入，允许处理可重试错误后再次保存；revision 冲突要求关闭后重开。旧 setIdleOptions / setAppearance 接口保留，直接、即时的既有调用不改写。
- 表盘卡片增加 Tab 焦点、Enter/空格及无障碍选择入口，焦点有边框提示；确认和设置窗口宽度受可用区域约束，参数输入补可读名称。
- 桌面控制页对配置占用、目录、写入和备份失败增加可读提示。

Android ControlPanelActivity / PanelIdleController：

- 同时记录 Activity 是否恢复、最近的窗口焦点回调，收到失焦时暂停本面板空闲状态并清理未完成的键/触摸持有；恢复焦点后重新等待完整空闲时长。
- 焦点通知和生命周期顺序独立处理，不修改共享 Activity、键盘插件、配对或其他界面。首次还没有焦点回调时沿用已恢复 Activity 的原行为。
- 重复的 active 通知不再清空正在进行的唤醒手势/按键，也不关闭已显示的表盘或重新延长计时。
- 沿用整个首次唤醒触摸/组合键被消费的规则，配置表盘样式变化不自动执行控制按钮。回后台仍停止 Activity 本地 tick。

平台依据：[Android 窗口焦点回调](https://developer.android.com/reference/android/app/Activity#onWindowFocusChanged(boolean)) 明确其与生命周期独立，系统通知面板可能取得焦点但不暂停 Activity。本批处理的是面板自身的输入和计时状态，不是全系统焦点或输入锁。
