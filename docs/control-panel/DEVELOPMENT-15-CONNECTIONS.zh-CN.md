# 阶段十五：连接、会话和多设备开发

日期：2026-11-12。继续遵循先完成全部功能开发、最后统一测试。本批仅控制面板协议/插件/会话、相关资源、用例和说明；不修改 KDE 共享网络、配对、Device、其他插件或既有音量协议。

## 对应目标

CONN-01 / CONN-02 要求已配对后读取配置、可靠同步与重连，断线禁用、不补发离线点击，多控制端不串请求；COMPAT-01 要保留旧端兼容和原 KDE 功能。本批补齐代码中的迟到响应与回调边界，不把静态分析当作这些需求已通过运行验收。

## 本批修改

- 桌面在完成握手后给配置、页状态、结果和天气追加当前控制器 sessionId；图标沿用原严格会话字段。握手前主动配置/状态仍可省略标记。
- Android 拒绝明确指向其他会话的响应，在处理协议版本错误前先检查会话，避免旧包把新会话标为失败。首次接受带当前会话标记的有效配置后，不再接受省略标记的同类响应。
- 保留旧服务端无标记响应的兼容路径；这个路径无法提供同等会话隔离，不宣称旧体验版具备新保护。配置结构和固定样本、protocolVersion=1 及原请求字段不变，详情见 PROTOCOL.zh-CN.md。
- Android 发送入队和状态改变复用 PanelSession 的同步边界，检查捕获的会话仍有效。动作包固定使用创建动作时的 sessionId，不在重连后换成新会话 ID 再发送。
- 每次插件会话有自己的捕获 ID 的 tick。旧定时任务和异步发送失败回调在重连后失效，不改变新会话状态、同步重试数或待处理请求。
- 取消配对/不可达时拒绝新请求并转为离线；接收入口同样检查配对及可达，不依赖插件销毁的时序窗口。共享 Device 仍只读，未改其行为。
- 动作遇到 invalid_session 时重新握手，沿用递增序号；不自动补发按钮。success 与 error 矛盾的结果不再确认请求。手动同步和配置变化清除旧动作反馈，request_expired 增加可读提示，明确“未重新执行”不等于“从未执行”。
- 桌面原生启动若重入事件循环并收到新会话握手，旧完成结果带原会话标记，不污染新会话去重缓存。
- 多控制端仍共享运行时活动页，这是既定设计；每个设备的会话、序号、去重和既有 Run Command 命令读取保持各自作用域。没有把全部手机改为独立页面，也没有改写其他 KDE 功能。

本批同步锁只包围本会话的状态修改与既有异步发送入队；图标传输的 update/receive/tick 在此锁外调用，避免与图标模块已有锁形成反向嵌套。仍需最终并发/重连和长期运行验证，不能从锁存在推断无竞态。

## 最终用例准备（未运行）

Android ControlPanelPluginTest 新增：

- 有标记配置建立绑定；旧/错误类型标记、迟到的版本错误、降回无标记的状态/结果/配置被拒绝。
- 已销毁会话的 tick 和发送失败回调不影响重连后的会话，当前会话的失败仍生效。
- 取消配对和不可达时不发送新请求；会话失效重新握手但没有自动重放动作。
- success/error 矛盾不能确认待处理按钮。
- 两个不同设备的插件实例分别请求、确认和持久化，不接受对方的会话结果；原有无标记旧端测试继续保留。

Windows PanelPeerTest 新增：

- 握手后的配置、结果和广播状态标记各自会话；握手前无标记行为保留。
- 两个控制器相同 requestId 仍独立执行/缓存不同结果，当前页继续共享。
- 旧会话请求被拒绝时不改变新会话；模拟原生执行重入握手后，旧结果不占用新缓存。

这些测试只有源代码，未运行、未计算通过数量，不冒充真实双设备或真实原生重入验证。
