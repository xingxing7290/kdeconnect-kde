# 智能家居（Home Assistant）表盘

本页说明控制面板的智能家居功能：由 Windows 端连接家里的 Home Assistant，把实体状态转发到 Android 平板，在表盘上显示、在手机端控制。

## 1. 为什么由电脑连接

```
Home Assistant  ←— WebSocket —→  Windows 桌面端  —— KDE Connect —→  Android 平板
   (局域网)                      (唯一持有令牌)                       (显示 + 控制)
```

- 只有桌面端保存 HA 地址和长期访问令牌，手机端永远拿不到凭据。
- 桌面端常驻在 `kdeconnectd` 守护进程里，平板只要能和电脑保持连接，就能看到状态。
- 平板侧不直接访问 HA，因此不需要平板处在同一网段。

## 2. 在 Home Assistant 里准备令牌

1. 打开 HA 网页，点左下角用户名 → 「安全」或「长期访问令牌」。
2. 新建令牌，命名随意（例如「KDE 控制面板」），复制生成的字符串。
3. 令牌只显示一次，请立即保存。

## 3. 在电脑上配置

1. 打开控制面板，左侧选择「表盘选择」，点「智能家居」按钮；也可以在左侧「智能家居」页点「配置」。
2. 填写：
   - **地址**：`http://<HA 的局域网 IP>:8123`，例如 `http://192.168.1.5:8123`
   - **长期访问令牌**：粘贴上一步的字符串
   - 勾选「启用智能家居」
3. 点「保存」。状态行应显示「已连接 Home Assistant，正在实时同步」。
4. 点「添加实体」，从已读取的列表中勾选要显示的设备；列表上方有搜索框，可按名称或实体 ID 过滤（实体多时很有用）。
5. 每个已选条目可以：
   - 改显示名称（留空则用 HA 里的名称）
   - 填分组（可选，例如「客厅」；表盘和手机端会按分组分段显示）
   - 用 ↑ ↓ 调整顺序
   - 移除

支持的三类实体：

| 类型 | 说明 | 未进入表盘时的行为 |
|---|---|---|
| `switch` | 开关 | 显示开/关 |
| `light` | 灯 | 显示开/关；开启时显示亮度百分比 |
| `sensor` | 读数（温度、湿度、电量等） | 只显示当前值与单位 |

## 4. 在平板上使用

1. 确保平板与电脑已配对且在线。
2. 电脑上「表盘选择」里选择「智能家居」表盘，或让平板空闲自动进入表盘。
3. 表盘布局：**设备列表为主体并按分组分段**，时间以小字号固定在右上角（按需求如此设计，不做历史趋势）。
4. **表盘是只读的**：空闲表盘会把「唤醒」那一次触摸整个吞掉（`PanelIdleController.touch`），所以卡片上没有可点的开关。
5. 要操作设备：轻触屏幕回到控制面板 → 顶部的房子图标（仅在有实体时出现）→ 打开「智能家居」列表。
   - 开关、灯右侧是开关控件，点一下即切换
   - 灯开启时，开关左侧有 `－` / `＋` 按 10% 步进调亮度
   - 读数类只显示当前值

平板上的离线提示分几种：

- 「尚未配置 Home Assistant」：电脑端还没填地址或没启用
- 「电脑未连接 Home Assistant」：电脑离线或 HA 不可达
- 「正在连接 Home Assistant…」：正在握手或验证令牌
- 「数据已过期」：超过 45 秒没收到新状态（电脑端每 30 秒有一次兜底读取并回推，正常不会出现）
- 「还没有设备」：已连接但还没勾选实体

连接错误码（如 `hass_auth_invalid`）在两端都会显示为中文说明，不再直接暴露机器码；点开关后，桌面和手机页面都会显示「最近一次操作」的结果，HA 拒绝时能看到具体原因。

## 5. 在电脑上直接控制

左侧「智能家居」页的「当前显示的设备」列表可以直接操作，不必先去平板：

- 开关、灯右侧有「打开 / 关闭」按钮
- 灯开启时有 `－` / `＋` 按钮，按 10% 步进调亮度
- 读数类只显示当前值

电脑上的操作由界面进程直接调用 HA 的 `call_service`；HA 状态变化后，守护进程会照常把新快照推给平板，所以两端显示始终一致。

## 6. 协议

沿用 `kdeconnect.controlpanel.*` 命名：

| 包类型 | 方向 | 载荷 |
|---|---|---|
| `kdeconnect.controlpanel.hass` | 电脑 → 平板 | `status`、`error`、`fetchedAt`、`entities[]`、可选 `lastCommand` |
| `kdeconnect.controlpanel.hass_command` | 平板 → 电脑 | `sessionId`、`entityId`、`action`（`toggle`/`turn_on`/`turn_off`）、可选 `brightness` |

`entities` 每项只含展示所需字段：`id`、`type`、`name`、`state`、可选 `group`/`unit`/`brightness`/`order`。
头像、颜色、历史等大字段在电脑端就被裁掉，避免包体过大。字符串在电脑端统一截断并去掉控制字符，因此单个异常的名称不会让整包被手机丢弃。

## 7. 安全约束

- HA 地址与令牌存放在配置的 `hass` 私有段，**不进入 `publicConfig()`**，因此不会同步给手机。
- `hass_command` 必须携带**当前会话**的 `sessionId`，与 `config`/`action` 请求走同一套校验；旧会话的指令会被丢弃，避免重放。
- 配置导出（`panelportable`）会把 `hass` 段的 `url` 与 `token` 清空，只保留实体清单；导入时地址与令牌始终取本机已有值，**文件里的凭据一律不采信**。
- 平板发来的指令会校验实体是否在已选列表中、类型是否可控制、动作是否合法。
- 单个服务调用失败只在该条目上提示，不会把整个表盘标记为断开。

## 8. 已知限制

- **旧版 APK 兼容**：桌面下发配置时会检查平板是否声明支持 `kdeconnect.controlpanel.hass`。若平板仍是 alpha.5 等旧版本，配置里的 `dialId` 会被临时降级为 `digital`，避免旧版控制面板因不认识 `hass` 而整份配置校验失败、完全打不开；桌面「智能家居」页会同时提示升级 APK。升级后无需改配置，重新连接即恢复。
- 仅支持 `switch`、`light`、`sensor` 三类；空调（`climate`）、窗帘（`cover`）等尚未支持。
- 不做历史趋势，只显示当前值。
- 实体上限 120 个，可选列表最多缓存 500 个。
- 令牌明文保存在本机配置文件中，请确保电脑账户本身安全。
- 控制面板窗口打开时，界面进程与守护进程会各自连一条 HA WebSocket（一条用于手机推送，一条用于配置界面的实体列表），因此 HA 的「集成 → 日志」里会看到两个客户端。
