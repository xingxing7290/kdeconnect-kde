## 本批开发

- Windows 输出选择先读取 eConsole、eMultimedia、eCommunications 的原端点，任一角色读不到则拒绝写入。已全部指向目标时不重复操作。
- 逐角色切换并回读；失败或并发变化时逆序尝试恢复本次已写入角色。对已被外部改成第三个设备的角色不盲目覆盖。全部原角色回读一致才返回普通失败；否则返回 default_output_partial_failure，提示检查 Windows 声音设置。
- 原生角色设置并非原子事务；拔插、音频服务失败和并发切换可能使回滚不完整，不能承诺无条件恢复。显示的音量和默认勾选仍以媒体角色回读为准。应用显式绑定的输出或已经打开的流不保证随系统默认立即迁移。
- 桌面增加音量错误可读提示和三角色切换说明。手机仍沿用原 System Volume 协议，它没有逐次写入结果确认，不把状态刷新冒充完整错误反馈。
- 文件、目录、网址与快捷方式原生打开补 COM 初始化配平，区分目标不存在、无默认关联、缺依赖、权限、取消和启动环境失败；不自动提权，不绕过安全提示。EXE 的结构化参数及工作目录保持不变。
- 快捷键发送前检查目标按键和修饰键是否被按住，再检查前台窗口有无变化；插入不完整时仅尽力补发抬键，不宣称绝对清理成功。此检查缩小误发窗口，不构成前台焦点锁。
- 智能跟随增加无法读取/宿主内实际程序无法识别的错误状态。保留最后稳定结果，但在错误未消除时禁用复制和绑定旧结果；仍允许手工填写程序名，不提权。
- 对 ApplicationFrameHost 可见 CoreWindow 子窗口尝试查询实际进程名。这是有限的兼容策略，不代表全部 UWP、WinUI 或提权窗口已兼容；不读标题、文档或命令行，不同步完整路径。
- 两端普通配置更新保留仍有效的运行时当前页；显式改变活动页、改变模式、删除当前页及重新连接时重新按有效配置选择，不改变协议或离线执行限制。
- Android 增加上述原生启动错误的对应提示，中英文资源键同步。
